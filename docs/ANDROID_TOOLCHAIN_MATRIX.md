# Android Toolchain Matrix

This document describes the build toolchain versions used across the Star System Sorter project, specifically for Android builds.

## Overview

The project uses **two separate Android build environments** that are intentionally decoupled:

1. **Flutter Module** (`runner_game/.android/`) - Uses Flutter's generated Gradle configuration
2. **React Native Host** (`android/`) - Uses React Native's Gradle configuration

These environments remain decoupled until an integration strategy is chosen (see task 9.5.0).

## Toolchain Versions

### Flutter Module (`runner_game/.android/`)

Generated by Flutter's module template and managed by Flutter tooling:

- **Gradle**: 8.x (from Flutter template)
- **Android Gradle Plugin (AGP)**: 8.x (from Flutter template)
- **JDK**: 17 (required by Flutter stable)
- **Flutter**: 3.35.x stable (via fvm)
- **Dart**: Bundled with Flutter

**Location**: `runner_game/.android/gradle/wrapper/gradle-wrapper.properties`

**Notes**:
- Do NOT manually bump Flutter module to Gradle 9.x yet
- Flutter template controls these versions
- Upgrading requires Flutter SDK update or manual template modification

### React Native Host (`android/`)

Managed by React Native and project configuration:

- **Gradle**: 8.13 (stable, Flutter-compatible)
- **Android Gradle Plugin (AGP)**: 8.12+
- **JDK**: 17+
- **React Native**: 0.82+
- **Node.js**: 20+

**Location**: `android/gradle/wrapper/gradle-wrapper.properties`

**Notes**:
- RN host uses Gradle 8.13 for Flutter compatibility
- Avoids Gradle 9.x issues with Flutter module integration
- Can be upgraded to 9.x after Flutter adds support

## Why Two Separate Toolchains?

The Flutter module and React Native host use separate build configurations to:

1. **Avoid version conflicts**: Flutter's template uses Gradle 8.x, while RN uses Gradle 9.x
2. **Maintain independence**: Each can be built and tested separately
3. **Defer integration complexity**: Integration strategy (AAR vs include) chosen in task 9.5.0

## Integration Strategy (Task 9.5.0)

Two options for integrating Flutter module into RN host:

### Option A: Direct Include (include_flutter.groovy)
- Flutter module included directly in RN build
- Requires compatible Gradle/AGP versions
- May require bumping Flutter module to Gradle 9.x
- **Status**: NOT USED (causes Gradle plugin conflicts)

### Option B: Prebuilt AAR (Recommended) ✅ CHOSEN
- Build Flutter module separately: `flutter build aar`
- Publish to `mavenLocal()` or local Maven repository
- RN host depends on prebuilt AAR artifact
- **Decouples host's Gradle/AGP from Flutter's**
- Avoids version conflicts
- **Status**: IMPLEMENTED

**Current Status**: ✅ **Option B (AAR method) chosen and implemented**. The Flutter module's `.android/` directory is used to BUILD the AAR (`flutter build aar`), but the RN host consumes the prebuilt AAR artifacts from `runner_game/build/host/outputs/repo/`, not the `.android/` directory directly.

## Build Commands

### Flutter Module Only

```bash
cd runner_game
fvm flutter build aar
```

This builds the Flutter module independently using its Gradle 8.x toolchain.

### React Native Host Only

```bash
cd android
./gradlew assembleDebug
```

This builds the RN host using its Gradle 9.x toolchain.

## Troubleshooting

### Gradle Version Mismatch

If you see Gradle version conflicts:

1. Check which build you're running (Flutter module vs RN host)
2. Verify you're using the correct Gradle wrapper for that build
3. Do NOT try to unify versions until integration strategy is chosen

### JDK Version Issues

Both toolchains require JDK 17+:

```bash
java -version  # Should show 17 or higher
```

If using multiple JDK versions, set `JAVA_HOME` appropriately:

```bash
export JAVA_HOME=/path/to/jdk-17
```

### Flutter Module Build Fails

Ensure Flutter stable is installed and active:

```bash
fvm flutter doctor -v
fvm flutter --version
```

## CI/CD Considerations

### Smoke Test (Non-Hosted)

CI should run Flutter module smoke test to catch toolchain drift:

```bash
cd runner_game
fvm flutter doctor -v
fvm flutter build aar
```

This verifies the Flutter module builds independently before integration.

### Release Builds

On every release build, run `fvm flutter build aar` to keep artifacts fresh.
