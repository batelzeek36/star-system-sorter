## BRIDGING (RN ↔ Flutter)
**Message schema (JSON)**
- RN → Flutter (MethodChannel `s3/game/cmd`):
  - `{"type":"start","payload":{"game":"horde"|"runner","seed":"<string>","team":"Orion"|"Sirius"|...}}`
  - `{"type":"pause"}`
  - `{"type":"resume"}`
  - `{"type":"quit"}`
  - `{"type":"set-music","payload":{"pack":"Sirius"}}`
- Flutter → RN (EventChannel `s3/game/events`):
  - `{"type":"result","payload":{"game":"runner","score":12450,"durationMs":284000,"suspect":false,"clientHash":"...","metrics":{"kills":42,"coins":121}}}`
  - `{"type":"error","payload":{"code":"CHEAT_DETECTED","message":"..."}}`
  - `{"type":"ready"}` (engine ready)
  - `{"type":"state","payload":{"fps":60}}` (optional debug)

**Android**
- Add Flutter module to RN app:
  - `settings.gradle`: `include ':flutter_module'`
  - `app/build.gradle`: `implementation project(':flutter_module')`
- Cache engine in `Application`:
  - Create `S3Application.kt`: init `FlutterEngine`, executeDartEntrypoint, put into `FlutterEngineCache` as `"s3_engine"`.
- Launch from `GameBridgeModule.kt`:
  - `startActivity(FlutterActivity.withCachedEngine("s3_engine").backgroundMode(FlutterActivityLaunchConfigs.BackgroundMode.transparent).build(context))`
- Wire MethodChannel/EventChannel:
  - Channel names above; post JSON strings.

**iOS**
- Add to Podfile:
  - `flutter_application_path = '../games/flutter_module'`
  - `install_all_flutter_pods(flutter_application_path)`
- Cache engine in `AppDelegate.swift`:
  - `let engine = FlutterEngine(name: "s3_engine"); engine.run(); GeneratedPluginRegistrant.register(with: engine)`
- Present VC in `GameBridge.swift`:
  - `let controller = FlutterViewController(engine: engine, nibName: nil, bundle: nil)`
- Set up `FlutterMethodChannel` and `FlutterEventChannel`.

**RN side**
- `NativeModules.GameBridge.open(game, seed, team)`
- `NativeModules.GameBridge.close()`
- `DeviceEventEmitter.addListener('S3GameEvent', handler)` (wrap in TS class with typed events).

## GAMES (Flame, deterministic, async team competition)
Two mini-games:
1) **Horde Survival** (10 min cap): top-down waves + level-up choices (Vampire-Survivors-ish)
2) **Side Runner** (3–5 min): auto-run, jump/dash, hazards, collectibles

Determinism:
- Seeded RNG (`PCG` or `XorShift`), fixed timestep, frame-indexed input timeline.
- Record inputs (down/up w/ frame); compress via RLE/delta; compute `clientHash`.
- **Ghosts**: use teammates’ saved input timelines with same seed; render as translucent silhouettes.

Anti-cheat:
- Server re-sim (Node packages/games-headless) must recompute the same score from `{seed, inputs, version}`.
- Clamp max speed/DPS; validate intervals/state transitions; mark `suspect=true` if drift > tolerance.

Team scoring & seasons:
- Daily team score = `sum(top K) + median(all)`, with `K = clamp(round(sqrt(N)), 5, 25)`.
- Weekly seasons aggregate dailies. Transparent formula in UI.

Music & haptics:
- Default soundtrack per star system (mapping via JSON); allow override.
- In Flutter: audio mixer with layered stems; in RN: preference UI + persistence.

## SCORER (DETERMINISTIC; TS LIB USED BY RN)
- Inputs: HD extract (type, authority, profile, centers, channels, gates).

## SAFETY & MODERATION (MANDATORY)
Scope: DMs, star system rooms, posts/comments, **avatar generator** prompts/outputs.

**Hard block**:
- Sexual content/nudity/fetish; any sexualization of minors (report + perma ban)
- Harassment/hate/slurs/threats/bullying/stalking/doxxing
- Extremism promotion; credible threats; self-harm instructions
- Explicit gore; illegal solicitation; scams/impersonation; deepfakes/face swaps/revenge porn
- Creepy/sexualized content about young-looking characters or age roleplay
- Sharing others’ PII (birth data, addresses, phones, financial)

Age gating: default 18+. If under-18 later, avatar = abstract crests only; DMs off.

Implementation:
- `ModerationService` TS interfaces on RN side:
  - `checkText({text, context, authorId}) -> { decision:'allow'|'soft_block'|'hard_block'|'review', reasons:string[], severity:number, redactions? }`
  - `checkImage({prompt, bytes?, context, authorId}) -> ModResult`
- Pipeline: client pre-filter → server check → decision handlers:
  - `allow`: deliver; `soft_block`: block & show “Please rephrase…”; `hard_block`: reject with policy copy; `review`: queue & hide.
- Avatar gen: pre-sanitize prompts (allowlist abstract/crest/cosmic; block body/age/sexual terms; block real names). Post-check any generated image; discard on flag; show copy:
  - Soft: “That message breaks our community rules. Please rephrase and keep it kind.”
  - Hard: “This content isn’t allowed here. See Community Guidelines.”
  - Avatar: “We only support abstract, crest-style avatars. Try different words.”
- Rate limits: DMs ≤20/5min; rooms ≤8/min; links ≤3/hr; mentions ≤5/10min; new accounts = half limits.

Tests: text categories, avatar sanitizer, decisions, rate limits.
